# Mimo v4｜分層上下文記憶：設計、隱私及實測

**驗證日：2026-10-15。** 系統為教師虛構校園事件原型，不是正式的學生心理諮商或兒少危機通報服務。

## 為什麼不能只加長六個來回

原本公開 Gemini API 只拿最近 12 則（約 6 個來回）和 3 欄 thread（事件／在意的事／未解線索）。時間一久，原始發言會掉出視窗，摘要也可能把更正前的細節與已說清楚的事搞混。增加原話視窗只能延遲遺忘，不能持久保存特定的界線與已選策略。

## 正式部署的三層記憶

1. **近期原話**：最近 16 則訊息，保留自然回答的上下文、情緒變化和前次問題，避免重複盤問。
2. **可更新的結構化記憶**：Gemini **在同一次對話 API 呼叫中**產生 `memory.summary`、`facts`（學生所述事件，不等於查證事實）、`uncertainties`、`boundaries`（明確拒絕的引導）、`plans`（學生自己提出的策略）及 `milestones`（較早的重要主題）。逐輪修訂；若學生更正，應只保留新版本。內文每項有最大長度與數量限制，無資料庫或額外記憶模型呼叫。
3. **舊原話選擇性檢索**：在**同一分頁最近 80 則可見訊息**內，從不在近期視窗的孩子發言選取最多 4 則相關舊原話。以中文雙字重疊匹配、明確提及「最早／以前」時保留最早的學生陳述作為回溯線索。若後來有更正，新版 Gemini 指令要求以最近更正為準。這不是語意向量搜尋，複雜跨主題檢索仍可能失誤。

API 僅需 `POST /api/reflect-v2` 一次，傳遞 `history`、`archivedClues`、`thread` 與 `memory`；回傳自然回覆和新版本 `thread`／`memory`。**記憶不是驗證過的真相**。

## 留存、安全與孩子控制

- 公開版只限虛構案例；Gemini Key 仍在後端，瀏覽器不儲存教師密碼。
- 同一分頁的 `sessionStorage` 保存對話及工作記憶，24 小時有效；重新整理可以接續，關閉分頁通常就無法跨新分頁續聊，沒有登入帳號、跨裝置永久記憶或伺服器對話資料庫。
- 「重新聊天」會清除該分頁的對話和記憶。孩子可以點開「記得的故事重點」查看並透過下一句話更正；尚不具備逐欄位編輯介面。
- 對原話、舊發言及結構記憶保留公開模式個資樣式偵測；該偵測不能保證識別所有個資，不應在此輸入真實學生的敏感資訊。
- 立即傷人／自傷等固定安全分流仍優先於模型記憶。明確「不要換位」等界線，即使經固定回覆、未呼叫 Gemini，也會記入工作記憶並在刷新後保留。
- 雲端 Gemini 的記憶更新仍可能遺漏、過度推論或產生錯誤；必要時孩子可以更正，正式兒少應用仍需專業審查。

## 真實 API 與瀏覽器驗收結果

### A. 用 Gemini 真正測試「更正」與超出近期視窗的回想

- 初始虛構海報說「藍色星星」；後來明確更正為「綠色月亮」；測試後端回應中更新了 `memory.summary` 和 `facts`。
- 再送出 **16 則與海報無關的測試近期對話**，讓初始海報完全不在 `recent_turns`；僅憑較早已壓縮的 `memory`，Gemini 確實回答海報「綠色月亮」、最在意「沒先被問過」。
- 另一次明確更正「藍色星星→綠色恐龍」的真實 Gemini 請求，新的摘要、facts、milestones 均不再包含已被否定的星星事實。

### B. 正式 390px 手機 Chromium 瀏覽器

**12/12 項通過，0 個 JS pageerror。** 實際測了：Gemini 啟用、初次與第二次回覆、結構記憶產生／更新、展開查看記憶、sessionStorage 保存、刷新後恢復、超出近期視窗仍傳入舊摘要、Gemini 正確回想綠色月亮、拒絕換位不呼叫模型仍保存界線、無水平溢出。

此處 **42 則是注入瀏覽器分頁的合成歷史訊息，不是 42 次真實 Gemini 呼叫**；隨後詢問歷史事件則確實呼叫正式 Gemini。

### C. 單獨測第三層舊原話檢索

再次用正式手機 Chromium 瀏覽器注入 42 則測試歷史，**把摘要清空**，最初的學生原話為「那張海報上畫的是綠色月亮」。詢問很久以前的圖案時，修正版成功把最早原話作為 `archivedClues` 送至 Gemini，模型實際回答「綠色月亮」。

最初這項測試曾失敗：前端在發送新輸入時另有一個殘留的 **30 則舊裁切**，會把最初原話丟掉。已將這條路徑修正為 80 則並以同一失敗案例重測通過。此故障沒有被隱藏。

### D. 離線與安全回歸

- `qa/memory-smoke.mjs`：**9/9** 通過，包含16則近期視窗、舊原話、明確拒絕、個資樣式攔截、高風險優先。
- `qa/safety-smoke.mjs`：**8/8** 通過，包含傷人／物品摔落／拒學／拒絕換位／否定句、個資及公開虛構情境限制。

離線測試無法證明所有真實兒少情境都安全，也不代表長時間記憶永不遺失。結構摘要是有容量的、模型本身也可能出錯，需要讓使用者更正。

## 已修改的檔案

- `reflect-lab/api/reflect-v2.mjs`：新長期記憶 Schema、更新指令、第三層舊原話輸入、個資與安全檢查。
- `reflect-lab/chat.js`：80 則分頁可見歷史、16 則近期模型原話、局部早期回溯、拒絕界線及分頁記憶保存。
- `reflect-lab/chat.css`：可點開、對兒童負擔較低的「記得的故事重點」。
- `reflect-lab/qa/memory-smoke.mjs`：可重跑的後端回歸測試。

**下一步建議：** 如果未來真的要記住跨天或跨裝置的真實學生經驗，必須先設計身分權限、監護人及學生告知同意、最低限度蒐集、保存期限、刪除權限、資料加密、學校輔導員接手和通報 SOP；不能直接把目前的 sessionStorage 換成永久資料庫就讓學生使用。
