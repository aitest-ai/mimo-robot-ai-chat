# Mimo v3｜對話記憶與使用體驗修正紀錄

日期：2026-10-15

## 起因與三個確認的根因

使用者指出：① Mimo 感覺不記得前文；② 首頁與對話流程不夠吸引人；③ 等待時反覆說「我想想」類的話很不自然。

檢視正式版 `chat.js`、`chat.css`、`index.html`、`api/reflect-v2.mjs` 後，找到以下根因：

1. 公開 Gemini API 實際只接收最近 **6 則訊息（約三個來回）**；重新整理後前端的 `state.history` 和 `thread` 都會消失。
2. 主要畫面只呈現最新一則 Mimo 回應與孩子的最後一句話，完整對話被折疊，學生看不到自己與 Mimo 的對話正在延續。
3. `replyTo()` 每次請求 Gemini 前都呼叫 `speak('我在聽，慢慢來。', ..., false)`。雖然這不是 AI 真正的回答，卻在畫面上反覆覆蓋正在讀的話。

## 真正執行的修正

### A. 前後文、主線與當前分頁記憶

- 伺服器：公開 Gemini 歷史由最近六則擴充至**最近十二則（約六個來回）**，各訊息長度另限制；保留結構化 `thread.event`、`thread.importance` 和 `thread.openLoop`，如模型某回合回傳空值，不清掉先前主線。
- 前端：聊天可見清單最多保留 30 則訊息，送出請求時附帶最近 12 則、故事主線、陪伴方式及前次回應技巧。
- 在**公開虛構情境**下，以瀏覽器 `sessionStorage` 存放最小必要對話狀態，允許同一分頁重新整理後接續；只保留約一天內的同分頁紀錄。
- 不保存 Gemini API Key、教師測試碼、學生身分、正式用戶帳號。點選「重新聊天」會清空此分頁的故事狀態。這不是跨裝置帳號記憶，也不是已通過兒童個資審查的資料保存機制。
- 在聊天標題旁用輕量提示顯示「我記得我們剛才聊到……」，方便使用者確認哪個焦點被暫存。此為**模型工作記憶摘要**，不是已核實的客觀事實。

### B. 真正的聊天體驗

- 將隱藏歷史改成始終可見、上下捲動的「你／Mimo」聊天氣泡，輸入框固定在下方。
- 初始歡迎頁直接提供三個**虛構校園故事**入口（作品被改／分組沒被選／朋友不理我），開始後自動讓位給聊天紀錄。
- 手機尺寸下把 Mimo 機器人縮小，讓出空間給對話和輸入；聊天氣泡短時靠近輸入框，內容長時仍可捲動。
- 移除與陪伴模式重複的快捷選項。孩子仍可以選擇「先聽我說／幫我整理／一起找方法」，但不會被大量教材題目包圍。
- 維持安全分流與「找大人幫忙」入口；不預設實際諮商或通報能力。

### C. 停止假裝「我想想」

- 移除每次送出訊息後重複替換成「我在聽，慢慢來」的文字。
- 改用沒有台詞的三點點等待動畫，正式 Gemini 回覆抵達後才呈現機器人的回答。
- 當 API 額度不足、超時或公開虛構練習輸入遭個資規則阻擋時，在對話區顯示清楚的提示，**不要用假回覆掩蓋斷線**。

## 尚存限制

1. 公開情境為虛構練習，**不可輸入真實兒童的姓名、學校、心理危機或其他敏感個資**。
2. `sessionStorage` 只限目前瀏覽器分頁，通常關閉分頁就不會持續；不支援跨裝置、跨帳號或長期記憶。
3. API 僅將最近十二則訊息及短主線送至 Gemini；非常長的故事仍可能因摘要錯誤遺漏細節。需要更多真實用戶體驗測試和錯誤率衡量。
4. API 服務品質受 Google 模型額度影響；失敗後會顯示狀態並使用有限的本地備援，不得把備援當作 Gemini 回應。
5. 危機辨識與成人接手仍須真人專業、校方 SOP 和兒少隱私審查。
